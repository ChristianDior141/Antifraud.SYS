# Обоснование технологического стека Antifraud.SYS

Детальное объяснение, **почему выбран каждый инструмент**: что это, какие задачи
решает в проекте, какие были альтернативы и какие компромиссы.

| Слой | Технология |
|---|---|
| Frontend | React 18, TypeScript, Tailwind CSS, Redux Toolkit |
| Backend | FastAPI (Python 3.11), SQLAlchemy 2.0 async |
| Database | PostgreSQL 15 |
| Cache/Queue | Redis 7 |
| Auth | JWT (access + refresh) |
| Container | Docker + Docker Compose |
| API Docs | OpenAPI / Swagger |
| Async tasks | Celery (worker) |
| Object storage | S3 / MinIO |

---

## 1. Backend — FastAPI (Python 3.11) + async SQLAlchemy 2.0

**Что это.** FastAPI — современный async web-фреймворк на Python поверх Starlette
(ASGI) и Pydantic. SQLAlchemy 2.0 — ORM с полноценной асинхронной поддержкой.

**Почему выбран:**
- **Асинхронность (ASGI).** KYC/AML — это много I/O-операций (БД, внешние
  AML/KYC-провайдеры, файлы). Async-модель обрабатывает тысячи одновременных
  соединений без блокировки потоков — критично для 100k+ сессий.
- **Pydantic-валидация из коробки.** Все входные/выходные данные строго
  типизированы и валидируются (например, телефон в E.164, политика паролей).
  Меньше ошибок и уязвимостей на границе API.
- **Автогенерация OpenAPI/Swagger.** Документация и схемы создаются автоматически
  из кода — всегда актуальны, удобно для интеграторов и SDK.
- **Dependency Injection.** RBAC реализован элегантно через `Depends()`
  (`require_admin`, `require_compliance`, `require_analyst`) — контроль доступа
  на уровне каждого эндпоинта.
- **Производительность.** FastAPI — один из самых быстрых Python-фреймворков
  (на уровне Node/Go для I/O-нагрузок).

**Альтернативы и почему не они:**
- **Django** — мощный, но «батарейки» и синхронная ORM избыточны/тяжелее для
  чисто API-сервиса; async в Django менее зрелый.
- **Flask** — минималистичен, но требует много ручной обвязки (валидация, доки,
  async), нет встроенной типизации.
- **Node.js (Express/Nest)** — отличный async, но Python выигрывает для
  риск-аналитики/ML и работы с данными (pandas, scikit-learn в перспективе).

**SQLAlchemy 2.0 async:** неблокирующие запросы к БД через `asyncpg`,
декларативные модели, прозрачные типы (например, `EncryptedString` для шифрования
PII), готовность к Alembic-миграциям.

## 2. Database — PostgreSQL 15

**Что это.** Реляционная СУБД корпоративного уровня с ACID-гарантиями.

**Почему выбран:**
- **ACID и целостность.** Финансовые/комплаенс-данные требуют строгой
  консистентности и транзакций — это профильная задача реляционной БД.
- **Богатые типы и JSONB.** Гибрид: строгая схема + `JSONB` для полуструктурных
  данных (риск-факторы, параметры правил, метаданные событий) — без отдельной
  NoSQL-БД.
- **Мощные индексы и аналитика.** B-tree, частичные и составные индексы, оконные
  функции — нужны для скоринга, отчётности и быстрых выборок.
- **Масштабирование.** Read replicas, партиционирование таблиц по времени
  (транзакции, аудит), путь к шардингу (Citus) или распределённым БД
  (CockroachDB) для multi-region.
- **Open-source, без вендор-лока.**

**Альтернативы:**
- **MySQL/MariaDB** — слабее по JSONB, оконным функциям и расширяемости.
- **MongoDB** — гибкая схема, но слабые транзакции/целостность не подходят для
  финансов как основная БД.
- **Oracle/SQL Server** — дорого и вендор-лок.

## 3. Cache / Queue — Redis 7

**Что это.** In-memory хранилище структур данных: кэш, брокер сообщений, счётчики.

**Почему выбран (в проекте используется реально):**
- **Брокер и backend для Celery** — фоновые задачи (пересчёт риска, уведомления,
  скрининг, экспорты) уходят из request-цикла.
- **Rate limiting storage.** Лимиты на `/auth/*` хранятся в Redis → работают
  согласованно при нескольких инстансах backend (без него лимит был in-memory =
  SPOF при масштабировании).
- **Кэш справочников** (санкционные списки, страны риска), сессий, идемпотентных
  ключей — снижает нагрузку на PostgreSQL и ускоряет ответы.
- **Скорость.** Доступ за доли миллисекунды; кластеризация (Redis Cluster) для HA.

**Альтернативы:**
- **RabbitMQ/Kafka** — более «тяжёлые» брокеры; нужны на следующем этапе
  (event-driven), но для кэша+очереди задач Redis проще и закрывает обе роли.
- **Memcached** — только кэш, нет очередей и богатых структур.

## 4. Auth — JWT (access + refresh)

**Что это.** JSON Web Tokens — подписанные stateless-токены для аутентификации.

**Почему выбран:**
- **Stateless.** Сервер не хранит сессии в памяти → любой инстанс проверяет токен
  по подписи. Это и есть основа горизонтального масштабирования.
- **Access + refresh.** Короткоживущий access (минимизирует риск кражи) +
  refresh для продления без повторного ввода пароля.
- **Контроль и отзыв.** В токен добавлен `jti`; есть denylist (`revoked_tokens`)
  для реального logout/принудительного выхода — закрывает классический минус JWT.
- **Совместимость.** Естественно сочетается с MFA (TOTP), а в перспективе — с
  OAuth 2.1 / OpenID Connect через внешний IdP.

**Альтервативы:**
- **Серверные сессии (cookie + хранилище)** — проще отзывать, но требуют общего
  хранилища сессий и хуже масштабируются.
- **OAuth2/OIDC через IdP (Keycloak/Auth0)** — целевое решение для enterprise/SSO;
  JWT — фундамент, на который это ложится.

**Безопасность в проекте:** bcrypt-хеши паролей, политика сложности, блокировка
после N неудач, шифрование PII/MFA-секрета, security-заголовки.

## 5. Frontend — React 18 + TypeScript + Tailwind CSS + Redux Toolkit

**React 18** — индустриальный стандарт для SPA: компонентная модель,
огромная экосистема, конкурентный рендеринг. Подходит для насыщенных дашбордов
(инциденты, аналитика, аудит).

**TypeScript** — статическая типизация ловит ошибки на этапе сборки (важно для
большого UI с десятками страниц и API-контрактов); самодокументируемый код.

**Tailwind CSS** — utility-first: быстрый, консистентный UI без «расползания» CSS;
единый дизайн без тяжёлой UI-библиотеки.

**Redux Toolkit** — предсказуемое управление состоянием (аутентификация, роли,
данные между страницами); состояние auth персистится в localStorage.

**Сборка — Vite** — мгновенный dev-сервер и быстрый production-бандл (через `tsc`
+ Rollup); в Docker собирается в статику и раздаётся nginx.

**Альтернативы:** Angular (тяжелее, более «мнение»), Vue (меньше экосистема для
enterprise), чистый JS (нет типобезопасности).

## 6. Container — Docker + Docker Compose

**Почему выбран:**
- **Воспроизводимость.** Идентичное окружение на любой машине и в CI — «работает у
  меня» исчезает.
- **Изоляция сервисов.** db, redis, minio, backend, worker, frontend — каждый в
  своём контейнере, со своими зависимостями.
- **Compose** — оркестрация мультисервисного стека одной командой; healthcheck,
  тома, сети, профили (опциональный PgBouncer).
- **Путь к Kubernetes.** Образы Docker — основа для K8s/Helm и автоскейла на
  следующем этапе.

**Альтернативы:** ручная установка (невоспроизводимо), VM (тяжелее и медленнее
контейнеров).

---

## 7. API Docs — OpenAPI / Swagger

**Почему выбран:**
- **Автогенерация из кода** (FastAPI) — документация всегда соответствует
  реальным эндпоинтам и схемам, не устаревает.
- **Интерактивность.** Swagger UI (`/docs`) и ReDoc (`/redoc`) — можно вызывать
  API прямо из браузера; удобно для тестирования и приёмки.
- **Контракт для интеграций и SDK.** Из OpenAPI генерируются клиентские SDK
  (Java/Python/Node/.NET) и контракты для партнёров.

## 8. Дополнительно использованные (за пределами базовой таблицы)

- **Celery (+ Redis)** — асинхронные фоновые задачи и worker-процесс.
- **S3 / MinIO** — объектное хранилище документов (общее для всех инстансов,
  убирает локальный диск как блокер масштабирования); MinIO = S3-совместимое
  хранилище для on-prem/dev.
- **Alembic** — версионирование схемы БД (контролируемые миграции).
- **passlib/bcrypt, python-jose, cryptography (Fernet), pyotp** — пароли, JWT,
  шифрование PII, TOTP-MFA.
- **slowapi** — rate limiting.
- **boto3, phonenumbers, openpyxl, reportlab** — S3-клиент, валидация телефонов,
  экспорт Excel/PDF.

## Как стек соответствует требованиям

| Требование | Чем обеспечивается |
|---|---|
| Высокая нагрузка / async | FastAPI (ASGI) + async SQLAlchemy + asyncpg |
| Горизонтальное масштабирование | stateless JWT, Redis (rate-limit/кэш), S3 (файлы), Docker |
| Целостность финансовых данных | PostgreSQL (ACID, транзакции) |
| Фоновая обработка | Celery + Redis (worker) |
| Безопасность/соответствие | JWT+MFA, bcrypt, Fernet-шифрование, RBAC через Depends |
| Документируемость/интеграции | OpenAPI/Swagger, REST |
| Воспроизводимость/деплой | Docker + Compose (путь к K8s) |
